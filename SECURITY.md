# Security policy

Nam Book Studio processes user-supplied manuscripts, notes, citations, images, and build files. Treat them as untrusted and potentially sensitive.

## Report a vulnerability

Open a private GitHub security advisory for vulnerabilities in repository code or templates. Do not put credentials, private health information, student records, unpublished confidential material, or exploit details in a public issue.

## Runtime expectations

- Never copy secrets into project reports, prompts, generated books, logs, or examples.
- Keep patient, respondent, and student material synthetic or properly de-identified.
- Treat document metadata, comments, tracked changes, embedded files, and image metadata as possible disclosure channels.
- Do not execute macros or active content from source documents.
- Do not bypass paywalls, access controls, robots restrictions, or licensing terms.
- Network and publishing actions still require the authority expected by the active host; a skill never grants extra permission.

The release validator can flag common risks, but it is not a substitute for institutional privacy, legal, or security review.
