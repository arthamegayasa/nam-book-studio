# Pedagogy patterns

Choose a pattern because it resolves diagnosed learner friction. One strong device is preferable to several overlapping callouts.

## Pattern selection

| Learner friction | Useful pattern | Required check |
|---|---|---|
| Missing prerequisite | Micro-refresh or prerequisite link | Does not restart the whole subject |
| Abstract relationship | Concrete example, analogy, or diagram request | Analogy boundary is stated |
| Multi-step procedure | Worked example followed by faded support | Steps reflect verified practice |
| Confusable concepts | Contrast case or comparison table request | Differences are discriminating, not cosmetic |
| Persistent misconception | Predict, expose, explain, then retest | Correction explains why the intuition fails |
| Passive familiarity | Retrieval prompt or generation task | Answer is not exposed in the prompt |
| Weak transfer | Varied application or edge case | New context still tests the same objective |
| Heavy cognitive load | Chunk, signal, sequence, or progressive reveal | Essential qualifications remain visible |

## Core patterns

### Analogy

Name the target relation, map only the relevant parts, apply it once, then state where the mapping fails. Remove an analogy that needs more explanation than the concept.

### Worked example

State the goal and relevant information, model each decision, make tacit reasoning visible, and finish with a similar prompt containing less support. Do not let incidental story details carry the answer.

### Misconception repair

Describe the tempting belief fairly, show the observation it cannot explain, replace it with a stronger model, and ask the learner to apply the replacement.

### Retrieval

Ask the learner to recall, discriminate, sequence, calculate, explain, or apply. Match difficulty to the objective and provide feedback after an honest attempt opportunity. Scored banks and full distractor rationales belong to `$nam-book-assess`.

### Visual request

Request a visual only when spatial arrangement, sequence, comparison, hierarchy, mechanism, or a memorable conceptual metaphor is easier to learn visually. Provide the objective, message, required labels, evidence IDs, caption intent, and alt-text intent to `$nam-book-visuals`.

## Mode overlays

### Friendly explainer

Prefer Big Idea, Why It Matters, Tip, Remember, Warning, Myth versus Fact, Try It, and optional Technical Corner. Define jargon and keep the main path usable without the technical branch.

### Textbook

Prefer definition, proposition or principle, mechanism, evidence note, worked method, case application, comparison, limitations, synthesis, and self-check. Connect elements to the curriculum rather than using conversational labels by default.

### Exam preparation

Prefer Must Know, High-Yield, discriminating feature, Clinical Pearl, Exam Trap, memory aid, timed decision path, rapid review, and retrieval set. A memory aid must remain accurate and must not replace the underlying explanation.

## Density and accessibility

Do not target a visual or callout every fixed number of pages; pagination changes by format. Instead, detect long conceptual stretches without a change of representation and add only what improves learning. Use text labels in addition to color or icons, keep reading order explicit, and provide meaningful captions or alt-text intent.
